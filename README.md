# ARHEOSCAN

Қазақ тіліндегі STEM зерттеу сайты. Node.js 20+; npm тәуелділіктері жоқ.

## Іске қосу

```sh
npm run dev
```

Сайт: http://localhost:3000. Бірінші іске қосқанда сервер `.runtime/device-token` файлына жеке кілт жасайды. `firmware/berel_arheoscan/config.example.h` файлын `config.h` атымен көшіріп, осы кілтті енгізіңіз. Қаласаңыз өз кілтіңізбен ауыстырып іске қосыңыз:

```sh
DEVICE_TOKEN='озиниздин-узын-кездейсок-килтиниз' npm run dev
```

Сайт ESP32 режимінде ашылады. Дерек келмейінше нақты көрсеткіштер ойдан шығарылмайды. «Демо» режимі бұрынғы симуляторды қосады.

## ESP32-ні қосу

1. Arduino IDE ішіне Espressif **esp32** board package орнатыңыз, нақты платаңызға сәйкес ESP32 Dev Module таңдаңыз. Үлгі түпнұсқа ESP32 DevKit GPIO34/35/32 үшін жазылған.
2. `firmware/berel_arheoscan/config.example.h` файлын сол папкаға `config.h` атымен көшіріп, `.runtime/device-token` ішіндегі кілтті `DEVICE_TOKEN` мәніне енгізіңіз.
3. `WIFI_SSID`, `WIFI_PASSWORD`, `DEVICE_TOKEN` мәндерін толтырыңыз. Кілт сервердегімен бірдей болуы керек. Құпия мәндерді Git-ке жібермеңіз (`config.h` еленбейді).
4. `SERVER_URL` ішіне компьютердің **жергілікті желідегі IP мекенжайын** жазыңыз: `http://192.168.1.100:3000/api/measurements`. ESP32 үшін `localhost` жарамайды. Mac-та Wi-Fi IP мекенжайын System Settings → Wi-Fi → Details → TCP/IP ішінен көре аласыз.
5. ESP32 мен компьютер бір Wi-Fi желісінде болуы керек. Сервер 3000 портын тыңдайды. Телефоннан компьютердің LAN мекенжайын ашып, желі қолжетімділігін тексеріңіз.
6. `berel_arheoscan.ino` файлын құрылғыға жүктеңіз. Электродтарды қалыпты топыраққа қойып, GPIO27 → GND батырмасын басыңыз: 5 үлгінің орташа базалық мәні алынады.
7. Калибровкадан кейін құрылғы өлшемді әр 2 секундта жібереді. Сайттың ESP32 режимінде мәндер, соңғы қабылдау уақыты және өлшеулер журналы автоматты жаңарады. 15 секунд жаңа дерек келмесе, ескірген өлшем туралы белгі шығады.

**Маңызды:** бұл firmware — байланыс пен ADC оқудың дайын үлгісі. `readSoilSignal()` M/N кернеулерінің айырмасын салыстырмалы 0–100 шкаласына түрлендіреді; бұл кедергінің ғылыми расталған есебі емес. Қолданыстағы өлшеу алгоритмін осы функцияға енгізіңіз. Құрылғыдағы ADC кіріс кернеуі платаңыздың сипаттамасына сай болуы керек. GPIO34 (`A`) конфигурацияланған, бірақ үлгі сигнал есебіне кірмейді. LCD және buzzer бар қолданыстағы кодпен біріктіруді қажет етеді; осы байланыс үлгісі оларды басқармайды.

Ресми API: [Wi-Fi](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/wifi.html), [ADC](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/adc.html), [HTTPClient](https://github.com/espressif/arduino-esp32/tree/master/libraries/HTTPClient).

## Қолданыстағы ESP32 кодына біріктіру

Өз кодыңыздан келесі сұрауды жіберіңіз:

```http
POST /api/measurements
Content-Type: application/json
X-Device-Token: сервердегі-килт
```

```json
{
  "pointId": "B-07",
  "signal": 74,
  "baseline": 46,
  "moundId": "K-11"
}
```

`signal`, `baseline`: бірдей салыстырмалы шкаладағы 0–100 сандар. Сервер `deviation = abs(signal - baseline)` есептейді: <10 п.п. NORMAL, 10–<20 RECHECK, ≥20 ANOMALY. Бұл шектер экспериментпен расталмаған, оларды `telemetry.mjs` ішінде өзгертуге болады. Құрылғы жіберген `status` есепті ауыстырмайды.

Нақты GPS болғанда қосымша `"lat": 49.3333, "lng": 86.3667` өрістерін жіберіңіз (мысал координаталарын нақты далалық GPS мәндерімен ауыстырыңыз). Екеуі бірге қажет. GPS жоқ болса, өлшем журналда сақталады; ойдан шығарылған координатамен географиялық картаға түсірілмейді. `moundId` — расталған далалық жазбаға сәйкес ерікті қорған идентификаторы; үлгі оны әдепкіде жібермейді.

- `GET /api/measurements`: соңғы өлшем, тарих, қосылым күйі.
- `GET /api/events`: браузерге қайта қосыла алатын SSE дерек ағыны.
- `POST /api/measurements`: кілтпен қорғалған, валидацияланатын өлшем қабылдау.
- Соңғы 1000 өлшем `.runtime/measurements.json` ішінде сақталады және сервер қайта іске қосылғанда қалпына келеді.
- CSV экспорт барлық сақталған өлшемдерді жүктейді; сайт журналы соңғы 25 өлшемді көрсетеді.

Жергілікті HTTP байланысы үшін арналған. Интернетке шығарғанда Node серверін HTTPS артында орналастырыңыз және firmware transport-ты сертификаты тексерілетін HTTPS-ке ауыстырыңыз. Сервер файлдары, firmware конфигурациясы және тарих static route арқылы жарияланбайды.

## Археологиялық зерттеу картасы

- Жоба қоныстар, қорғандар және көне қала орындарын алдын ала зерттеу принципін көрсетеді.
- Leaflet 1.9.4 жергілікті сақталған; географиялық қабат — © OpenStreetMap contributors (интернет қажет).
- Бастапқы көрініс — Қазақстанның жалпы картасы; нақты ескерткіш орны белгіленбейді.
- Нысандар сызбасы — GPS координаталары жоқ шартты оқу мысалдары. Бұл нақты ескерткіштердің жоспары емес.
- Нақты өлшемдер картада құрылғыдан GPS координаталары келгенде көрсетіледі.
- Нысандар мен демо эксперименттер `data.js` ішінде өңделеді.
- Құрылғылармен үйлесімділік үшін `moundId` API өрісі және `firmware/berel_arheoscan` жолы сақталған; `moundId` зерттеу нысанының идентификаторы ретінде қолданылады.

## Тексеру және жинақтау

```sh
npm run check
npm test
npm run build
```

`dist/` — static сайт. **ESP32 тікелей байланысы үшін Node сервері керек**; тек static hosting-те демо мен карта жұмыс істейді, live API қолжетімсіздігі көрсетіледі. Толық нұсқаны осы папкадан `npm start` арқылы іске қосыңыз.

Бұл сессияда Arduino компиляторы және нақты ESP32 қолжетімсіз: firmware платада компиляцияланып/сыналмаған. Сервердің HTTP/SSE қабылдауы автоматты тесттермен тексеріледі.
